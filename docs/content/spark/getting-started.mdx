## Use Spark from source

This path matches the APIs in these guides. macOS 14+ on Apple Silicon is the primary development target.

### Prerequisites

Install Git, `nvm`, Bun **1.3.14**, full Xcode with first-launch setup complete, and CocoaPods. The checkout pins Bun in `package.json`'s `packageManager`; both `postinstall` and `npm run spark` invoke it, even when installing with npm. Spark requires Node **24.19.0 or newer**; the commands below use `nvm` to select the checkout's version. Native build tools are needed to build the source Runner and standalone app.

### Clone and prepare the SDK

```sh
git clone https://github.com/LegendApp/legend-spark.git
cd legend-spark
nvm install
nvm use
npm install
npm run spark -- sdk pack
npm run spark -- sdk build-runner
```

`pack` creates local SDK archives, patched native dependency archives, and Expo Desktop templates, and registers their manifest. It fetches pinned upstream inputs on its first run. `build-runner` compiles and registers a matching development runtime. The source SDK needs this matching local Runner.

### Create and run an app

From the framework checkout:

```sh
npm run spark -- create /absolute/path/to/MyApp
cd /absolute/path/to/MyApp
npm run macos
```

Edit `App.tsx` in the generated app. JavaScript changes use Fast Refresh. Native dependency or configuration changes can require a [custom development build](/spark/development#native-changes).

Creation accepts `--package-manager npm|pnpm|yarn|bun`. Existing projects use their `packageManager` field or lockfile. The calling manager is preferred for new projects, with npm as fallback.

### Build a standalone app

Stop the development session, then run from the generated app:

```sh
npm run build
npx --no-install spark open
```

The build embeds JavaScript in an ad-hoc-signed `.app` that runs without Metro. [Packaging](/spark/distribution) adds Developer ID signing and notarization with your credentials; publishing remains separate.

### Other source workflows

If a matching runtime is already available, register its location from the framework checkout instead of building a Runner:

```sh
npm run spark -- sdk register /absolute/path/to/SparkRunner.app
```

Keep the runtime at that path. SDK/native changes can make it incompatible.

For a shared Settings starter with desktop/mobile/web adapters, run from the checkout:

```sh
npm run spark -- create /absolute/path/to/MySettings --universal
```

Use its generated `macos`, `windows`, `ios`, `android`, and `web` scripts. Some mobile dependencies require a development build rather than Expo Go.

## Try the published preview

`@legendapp/spark@next` is the experimental `0.0.1-next.2` preview. The npm `latest` tag also points to this preview; it does not indicate a stable release. It predates the current source APIs, so examples in these guides may not work with it.

With Node **24.19.0 or newer** installed:

```sh
npx @legendapp/spark@next create MyApp
cd MyApp
npm run macos
```

The matching GitHub prerelease supplies patched dependencies and a macOS ARM64 Spark Runner, downloaded on first desktop launch. A compatible Runner launch does not require Xcode or CocoaPods. Keep the generated lockfile and project-relative `spark-packages/` archives so clones can reinstall the same inputs.

## Windows source development

Windows is a secondary source development path; native builds and runtime behavior still need validation, and production distribution is unsupported. On Windows 11, install the toolchain from the [Windows guide](https://github.com/LegendApp/legend-spark/blob/main/docs/windows-slice.md), including Visual Studio 2026 / MSVC v145 for the pinned RNW template.

From a source checkout:

```powershell
npm install
npm run spark -- sdk pack --platform windows
npm run spark -- sdk build-runner --platform windows
npm run spark -- create C:\dev\MySparkApp --platform windows
cd C:\dev\MySparkApp
npm run windows
```

The target defaults to the machine's native x64/ARM64 architecture, including ARM64 Windows in Parallels.
